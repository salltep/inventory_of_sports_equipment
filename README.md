## Описание проекта

Объект автоматизации — операционный учёт спортивного инвентаря учреждения. Система ведёт электронные карточки объектов: наименование, уникальный ID, тип, статус (исправен / в ремонте / списан) и количество.

**Цели системы:**

- перевод каталога имущества из бумажного формата в единую базу данных;
- прозрачное отслеживание движения инвентаря и выявление ответственных лиц;
- своевременная фиксация поломок и оперативное обслуживание оборудования.

## Пользователи и роли

| Роль | Возможности |
|---|---|
| **Управляющий** | полный доступ: добавление тренеров, добавление/списание/проверка инвентаря, отправка оборудования в ремонт |
| **Тренер** | ограниченный доступ: просмотр инвентаря, выдача и приём оборудования, первичная фиксация поломок |

## Основные функции

1. Авторизация по логину и паролю, регистрация новых пользователей.
2. Просмотр инвентаря, выдача и приём оборудования (тренер).
3. Добавление нового оборудования в базу данных (управляющий).
4. Отправка инвентаря на ремонт с выбором по ID.
5. Проверка и списание инвентаря.

## Архитектура

Приложение написано на Python и построено по классической многоуровневой архитектуре:

- **Presentation Layer** (`ui/`) — консольный интерфейс: меню, ввод и вывод данных, авторизация;
- **Business Logic Layer** (`services/`) — бизнес-логика: регистрация, проверка прав доступа, проверка данных, смена статусов инвентаря;
- **Data Layer** (`repositories/`, `models/`, `database/`) — модели данных (`dataclass`), репозитории с SQL-запросами и база данных SQLite.

Интерфейс обращается только к сервисам, сервисы — только к репозиториям, SQL-запросы находятся исключительно в репозиториях.

## Сборка и запуск

Требуется Python 3.10 или новее. Сторонние библиотеки не нужны.

1. Создать базу данных из схемы (один раз, в корне проекта):

```
python -c "import sqlite3; c=sqlite3.connect('database/inventory.db'); c.executescript(open('database/schema.sql',encoding='utf-8').read()); c.close()"
```

Внимание: скрипт `schema.sql` удаляет и заново создаёт таблицы, поэтому повторный запуск вернёт базу к исходному состоянию.

2. Запустить программу:

```
python main.py
```

## Выгрузка данных (JSON, CSV, XML, YAML)

Скрипт `export_data.py` выгружает таблицу `Operation` вместе со связанными данными (инвентарь и логин пользователя) в четыре файла в папке `out/` (папка создаётся автоматически):

- `data.json`, `data.xml`, `data.yaml` — связанные данные вложены в объекты `inventory` и `user`;
- `data.csv` — вложенные поля объединены в одну строку (`inventory_name`, `user_login` и т.д.).

Запуск (один раз установить зависимость, затем выгрузить данные):

```
pip install -r requirements.txt
python export_data.py
```

Чтобы выгрузить другую таблицу, достаточно изменить настройки `TABLE` и `RELATIONS` в начале `export_data.py`. Код выгрузки менять не нужно: SQL-запрос с `JOIN` строится автоматически (`repositories/export_repository.py`), а сериализация в четыре формата выполняется в `services/export_service.py`.
